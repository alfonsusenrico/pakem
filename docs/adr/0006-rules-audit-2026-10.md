# 0006. Rules audit decisions (2026-10)

- Status: Accepted
- Date: 2026-10-12

## Context

The owner reviewed every rule of framework 0.2.0, the organization profile, and the
personal profile in a rules audit: 232 rules checked against the Working Standard
Profile and against each other. The audit found rules contradicting their own
enforcement, rules looser or stricter than the profile, rules contradicting each
other, and project details stored as general rules. The owner decided 22 of them;
the remaining rules stay as written.

## Decision

1. Floor: ask before deleting data or files the current task did not create.
2. Floor: agents never merge or approve a merge request; the owner reviews and merges.
3. `default:mr-policy` now means: push the topic branch, open the merge request, and
   report its URL. Client repositories override it (the owner opens the merge
   request there, because it is visible to the client's team).
4. `default:branching` now means: `main` stays deployable; code changes go through a
   topic branch; documentation-only changes may go directly to `main`; a project may
   allow more through `## Overrides` and `af hooks install --protect-none`.
5. The repository's pre-push hook is the control for pushes to protected branches.
   Claude Code and Codex no longer deny every push to `main`; the guard and Codex
   rules still block force-pushing or deleting protected branches, and every other
   force push needs the owner. `af project check` warns when the hooks are inactive.
6. Unknown fields are rejected on inputs the project defines; third-party responses
   and webhooks are validated on the fields used, because providers add fields as a
   backward-compatible change.
7. Migrations must not change silently once applied: a runner checksum or a CI test
   comparing applied revisions with the migration files. Hand-written, idempotent,
   forward-only, and no autogenerate stay.
8. Light and dark themes apply to every UI, not only to `deployed` projects.
9. The two draft tool design bases are not adopted until the owner approves them.
10. A workspace-specific file name is removed from the core deny list and guard.
11. Personal profile: freelance records keep principles only; field lists and
    numbering formats belong to the proposal generator.

## Consequences

- MAJOR release (1.0.0): two floors and the meaning of two labelled defaults change.
- The digest changes (deletion floor), so every adopted repository needs
  `af project sync` after the release.
- Enforcement must be reinstalled per host (`af enforce install`) to drop the old
  push denies; until then hosts still block documentation pushes to `main`.
- A repository without active hooks has no control on pushes to `main`; adopted
  repositories install hooks, and `af project check` reports the gap.
- Organization-profile decisions from the same audit are recorded in that profile.
